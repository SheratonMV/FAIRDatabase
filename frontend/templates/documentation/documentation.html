PBK module (PBPK) /model

The PBK (physiologically-based kinetic) module is the pbpk plugin: the in-app catalogue, runner, and provenance surface for four FAIR PBPK models of PFAS exposure across pregnancy, lactation, and childhood.

What it delivers
  • A catalogue of FAIR PBPK models with readiness status, applicability domain, calibration ranges, limitations, and FAIR badges.
  • A simulation runner that integrates each model's ODE system and returns a concentration–time series plus scalar KPIs.
  • Four bundled, citable study models packaged as SBML + parameters + an interactive page.
  • Run persistence with content-hash caching, W3C PROV-JSON provenance, and side-by-side comparison.
  • Ontology enrichment — SBML CV-terms resolved to labels via the EBI OLS4 API.
  • Binary run artifacts (jpg/png/mp4/vtk) in a private Supabase Storage bucket with short-lived signed URLs.

How the simulation engine works

The heart of the module is a small SBML interpreter that compiles an SBML model into two Python functions — a right-hand-side _rhs(t, y, p) for the ODE solver and a _state(t, y, p) that reconstructs all observable variables — then integrates with scipy.

  • SBML → Python: _ast_to_py() walks the libsbml AST and emits an equivalent Python expression (arithmetic, exp/ln/log/abs/min/max/root, relational/logical ops, and piecewise as nested ternaries). Unhandled nodes raise ValueError.
  • Parse: constant vs. non-constant params separated; assignment rules topologically sorted by dependency; rate rules become the ODEs.
  • Compile: generated source is compile()d once and exec'd, so each step is a plain function call — not a per-step AST walk.
  • Integrate: solve_ivp with the stiff-system LSODA method (rtol=1e-6, atol=1e-9). A singleton parses/compiles the SBML once per worker.

Admin & RBAC /admin

The admin console manages user roles and per-dataset access grants. Every privileged action is recorded in an append-only audit table.

RouteRolesPurpose
/admin/usersadminList users and change roles. Writes _fd.role_audit.
/admin/datasets/<id>/grantsadmin, curator (owns)Grant / revoke dataset read access. Writes _fd.grant_audit.

Roles:

  • admin — upload, read/modify any dataset, manage roles & grants.
  • curator — upload + own datasets; modify/grant only what they own.
  • accessor — read only datasets explicitly granted to them.
  • visualizer — sign-up default; catalogue + aggregate stats only.

RBAC is layered: the login_required(*roles) decorator, handler-side ownership checks, and Postgres RLS. Implemented in src/admin.

Visualization /visualization

Render charts and aggregate views for datasets the current user is authorized to read. Implemented in src/visualization.

Aggregate statistics are also exposed via the Supabase edge function get-dataset-visualization, which re-checks ownership/grants independently of Flask (defense in depth).
