Federated Learning

Privacy-preserving distributed learning across sites — FedProx aggregation with (ε,δ)-DP via RDP accountant. Aligned with FAIRification.md §10 Phase 2.

Horizontal FL shares the same features across all clients (sites have the same schema). The simulation below mirrors the FedDeepInsight study protocol: FedProx training with Dirichlet non-IID partitioning and tight RDP-accountant DP.

API Quick Reference
POST  /fl/tasks
  {
    "dp_epsilon": 1.0,   // total ε budget (RDP accountant)
    "rounds_total": 10,
    "algorithm": "fedprox",   // or "fedavg"
    "simulation": true,
    "sim_alpha": 0.5,       // Dirichlet α — non-IID heterogeneity
    "sim_n_clients": 5,
    "mu": 0.01,             // FedProx proximal term (0 = FedAvg)
    "model_arch": {
      "type": "tabular_mlp", "input_dim": 10,
      "hidden_dims": [64,32], "output_dim": 1, "task": "regression"
    }
  }

Vertical FL shares the same patients across parties that hold different feature columns (split learning). Each party runs an LSTM SiteEncoder; a server-side MMoE top model aggregates embeddings and applies task-stratified (ε,δ)-DP to the embedding gradient before returning per-party slices.
